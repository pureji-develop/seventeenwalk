# 03. データ構造仕様

Go 実装の正は `backend/internal/` 配下の型定義とする。本ドキュメントはその意味論を示す。

## 型一覧

| 型 | パッケージ | 役割 |
|----|------------|------|
| `Tile` | `game` | 1枚の牌（id + kind） |
| `Kind` | `game` | `m1`…`chun` の種類 |
| `Deck` | `game` | 136枚生成・シャッフル・分割 |
| `Seat` | `game` | 座席 0 / 1 |
| `Phase` | `game` | ゲームフェーズ |
| `Player` | `game` | プレイヤー状態 |
| `WalkState` | `game` | 捨て合い進行 |
| `RoundResult` | `game` | 局結果 |
| `Yaku` / `Score` | `game` | 役・翻・満貫（4翻）判定 |
| `Game` | `game` | 1マッチのルール状態 |
| `PublicState` 等 | `protocol` | マスク済みビュー |
| `Envelope` 等 | `protocol` | WS メッセージ |
| `Client` | `ws` | 1接続 |
| `Room` | `room` | 最大2人の対戦部屋 |
| `Hub` | `room` | ルーム管理 |

## ドメインモデル関係

```
Hub
 └── Room (id)
      ├── Clients [0..2]*Client
      └── Game
           ├── Players [2]*Player
           │    ├── Wall  []Tile   // 配牌34
           │    ├── Hand  []Tile   // 手牌13
           │    ├── Pool  []Tile   // 捨て候補
           │    ├── River []Tile
           │    └── Score int/float  // 初期0・加点のみ
           ├── SideWall []Tile     // 脇山68
           ├── DoraIndicator *Tile
           ├── Walk *WalkState
           └── RoundResult *RoundResult
```

## フィールド意味（要約）

### Tile

- `ID`: 局内一意（0–135 など）
- `Kind`: `m1` / `ton` / `haku` 等
- `Code()` → kind 文字列（スプライト参照用）

### Kind 一覧（34種）

`m1`–`m9`, `p1`–`p9`, `s1`–`s9`, `ton`, `nan`, `sha`, `pei`, `haku`, `hatsu`, `chun`  
各4枚で計136。

### Player

- `ID` / `Name` / `Seat`
- `Score`: 累計得点の **×2 整数**（初期0、和了時のみ加算、減点なし。表示は `/2.0`）
- `Wall` / `Hand` / `Pool` / `River`
- `HandSubmitted`: BUILD 提出済み
- `Ready` / `Rematch`
- 接続実体は `Room`/`Client` 側（Game は I/O 非依存）

### Game

- `mu`: 全ミューテーションを保護
- `Seq`: ブロードキャスト用シーケンス
- `Round` / `TotalRounds` / `LeadSeat` / `ToAct`
- `SideWall` / `DoraIndicator` / `DoraKinds`（実ドラ種類のリスト）
- `WinnerSeat`: マッチ決着時のみ（規定対局終了後の高得点側）

### WalkState

- `TurnCount[2]`: 各0–17
- `MaxTurns`: 17

### RoundResult

- `Result`: `RON` | `DRAW`
- `WinnerSeat` / `LoserSeat`
- `WinningTile` / `Hand` / `Yaku` / `Han` / `Limit`
- `PointsAwarded`: 和了者への加点（流局は0）
- `ScoreDelta[2]`: 通常は和了者側のみ正、他方は0
- `Ack[2]`

### 得点（Score / Limit）

- **表ドラあり・裏ドラなし**
- **ダブル役満以上あり**（`YakumanCount` ≥ 2）
- **4翻以上のみ和了可**（符計算なし）。4翻未満のロン牌は**全待ちあがり放棄**（`AgariAbandoned`）
- **見逃しなし**: 4翻以上なら安目でも自動ロン
- あがり放棄後はフリテン同様、どの牌でもロン不可
- `Limit`: `MANGAN` / `HANEMAN` / `BAIMAN` / `SANBAIMAN` / `YAKUMAN` / `DOUBLE_YAKUMAN` / …
- 加点: 満貫+1 / 跳満+1.5 / 倍満+2 / 三倍満+3 / 役満×4（ダブル+8…）（**内部は ×2 整数**）
- **マッチ得点は単調非減（加点のみ）**
- プロトコル配信時のみ `float64(score)/2.0`
- **先行**: 毎局交代（連荘なし）。点数に親子差なし
- **同点終了は引き分け**（`winnerSeat: null`）

### Dora

- 脇山は34スタック×2。上＝表表示（下牌は不使用・裏ドラなし）
- `NextKind(indicator)` で実ドラ種類を得る
- 循環: 数牌9→1、風 `ton→nan→sha→pei→ton`、三元 `haku→hatsu→chun→haku`

## 不変条件（実装時チェック）

1. `Players` は seat と配列 index を一致（`Players[0].Seat == 0`）
2. DEAL 後、各 `Wall` は34枚、`SideWall` は68枚、合計136
3. BUILD 完了後、各 `Hand` は13、`Pool` は21、`Hand ∪ Pool = Wall`
4. WALK 中、切った牌は `Pool` から除去済みで `River` にのみ存在する
5. `TurnCount[seat] <= 17`
6. `Score` は減点しない（単調非減。和了者への加点のみ）
7. `Seq` は state/event 送信のたびに増加
