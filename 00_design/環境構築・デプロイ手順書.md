# 環境構築・デプロイ手順書（運用マニュアル）

本ドキュメントは、**SeventeenWalk（十七歩）** プロジェクトに新規参画した開発者向けのローカル環境構築手順、および本番環境へのデプロイ・SSL運用に関する手順をまとめたものです。

設計の全体像は [基本プロット.md](./基本プロット.md)・[00_仕様概要.md](./00_仕様概要.md)・[05_ディレクトリ構成.md](./05_ディレクトリ構成.md) を参照してください。  
マルチゲーム共有ホスト上でのサブドメイン追加手順は、リポジトリ直下の [デプロイ手順書.md](../デプロイ手順書.md) も参照してください。

---

## 0. 構成の要点

- **DB なし / 認証なし**（JWT・PostgreSQL・ユーザー登録は不要）
- 対局状態は **バックエンドのインメモリ**（Hub / Room）。再起動で進行中ルームは消える
- バックエンド API に `/api` プレフィックスは無い: `POST/GET /rooms`・`GET /ws`・`GET /health`
- 本番ドメイン例: `https://seventeenwalk.taimanpoker.com`

## 1. ローカル開発環境の構築

Docker Compose でバックエンド（Go）とフロントエンド（Vite）を起動します。ローカル compose には nginx / DB は含みません。

### 1.1. 前提条件

- Docker および Docker Compose がインストールされていること
- WSL2 または Linux 環境が推奨

### 1.2. 立ち上げ手順

1. リポジトリをクローンし、プロジェクトのルートディレクトリに移動します。
2. 以下を実行してコンテナをビルド・起動します。

   ```bash
   ./start_local.sh
   # または手動で:
   docker compose -f docker-compose.yml up --build -d
   ```

3. 起動後のアクセス先:

   - **フロント（Vite）**: `http://localhost:5175`  
     （他プロジェクトの 5173/5174 と衝突しないよう固定）
   - **バックエンド直**: `http://localhost:8080`
   - **ヘルスチェック**: `http://localhost:8080/health` → `ok`

Vite は `/rooms`・`/ws`・`/health` を `backend:8080` へプロキシします（`frontend/vite.config.ts`）。

Docker を使わずに動かす場合:

```bash
# ターミナル1
cd backend && go run ./cmd/server

# ターミナル2
cd frontend && npm install && npm run dev
```

### 1.3. 任意の環境変数

| 変数 | 既定 | 説明 |
|------|------|------|
| `PORT` | `8080` | バックエンド待受ポート |
| `TOTAL_ROUNDS` | `4` | 既定局数 |
| `BUILD_TIMEOUT_SEC` | `180` | BUILD 制限時間（秒）。`0` は無限 |

例:

```bash
TOTAL_ROUNDS=6 BUILD_TIMEOUT_SEC=120 docker compose -f docker-compose.yml up --build -d
```

### 1.4. 開発時のコツ

- **ホットリロード**: `frontend/src`・`backend/` の変更はボリューム経由で反映されます（backend は `go run` 再起動が必要な場合があります）
- **ログ**: `docker compose -f docker-compose.yml logs -f`
- **停止**: `docker compose -f docker-compose.yml down`
- **フロントの型チェック**（ホストで Node を使う場合）:

  ```bash
  cd frontend
  npm install
  npm run typecheck
  ```

  `node_modules` が root 所有で `EACCES` になる場合:

  ```bash
  sudo chown -R "$USER:$USER" frontend/node_modules
  ```

- **バックエンドテスト**:

  ```bash
  cd backend && go test ./...
  ```

## 2. 本番環境へのデプロイ

本番は `docker-compose.prod.yml` で次を起動します。

| サービス | イメージ / 役割 |
|----------|-----------------|
| `nginx` | `seventeenwalk-nginx` — HTTPS + ACME、`/rooms` `/ws` `/health` を backend へ、静的を web へ |
| `sw-web` | `seventeenwalk-web` — `container_name: seventeenwalk-web-1` |
| `sw-backend` | `seventeenwalk-backend` — `container_name: seventeenwalk-backend-1`（インメモリ） |
| `certbot` | Let's Encrypt 用ボリューム共有 |

イメージは GHCR（`ghcr.io/pureji-develop/seventeenwalk-*`）へ push する想定です。

### 2.1. 準備事項

- サーバーに Docker / Docker Compose があること
- ドメイン（例: `seventeenwalk.taimanpoker.com`）の A レコードがサーバー IP を向いていること
- ファイアウォールで `TCP 80` / `TCP 443` が開放されていること
- **必須の秘密情報（JWT / DB パスワード）はない**。任意で `TOTAL_ROUNDS` / `BUILD_TIMEOUT_SEC` を export 可能
- nginx はプロジェクト固有の `container_name`（`seventeenwalk-web-1` / `seventeenwalk-backend-1`）へ proxy します。他ゲームと `shared-net` を共有する場合、短名 `web` を使わないこと
- **対局はメモリのみ**です。`up -d --force-recreate` では進行中ルームは再開できません。デプロイ前に確認:

  ```bash
  curl -sS https://seventeenwalk.taimanpoker.com/health
  # ok であること（本文はプレーンテキスト）
  ```

### 2.2. ローカルでのイメージビルドと push

```bash
./build_deploy.sh
```

内容の概略:

1. `nginx` / `frontend/Dockerfile.prod` / `backend/Dockerfile.prod` をビルド
2. GHCR へ `seventeenwalk-nginx` / `seventeenwalk-web` / `seventeenwalk-backend` を push

### 2.3. サーバーでの反映

```bash
# ヘルス確認（任意）
curl -sS https://seventeenwalk.taimanpoker.com/health

cd /srv/seventeenwalk   # 配置パスは環境に合わせて変更
sudo docker compose -f docker-compose.prod.yml pull
sudo docker compose -f docker-compose.prod.yml up -d --force-recreate
```

初回やスタンドアロン起動時は:

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

### 2.4. 共有ホスト（taimanpoker）上での注意

複数ゲームを同じ Lightsail 等で動かす場合、ルートの [デプロイ手順書.md](../デプロイ手順書.md) のとおり:

1. メイン側 `nginx.conf` に seventeenwalk の upstream / server を追加（リポジトリ内 `nginx.conf` が参考）
2. アプリを `shared-net` に接続して起動
3. メイン側 certbot で `seventeenwalk.taimanpoker.com` の証明書を取得
4. メイン nginx を `nginx -t` → `nginx -s reload`

アプリ側イメージ更新後は、Docker 内部 DNS 再解決のため **メイン nginx の reload** も行ってください。

## 3. SSL証明書（Certbot）の運用について

`docker-compose.prod.yml` の `certbot` コンテナと `nginx` が Let's Encrypt 用ボリューム（`certbot-etc` 等）を共有します。

### 3.1. 初回取得の注意

初めて起動する際、ドメインが解決できない・証明書が無いと Nginx が起動エラーになることがあります。  
その場合はダミー証明書の配置や、共有ホスト側での `certbot certonly --webroot`（[デプロイ手順書.md](../デプロイ手順書.md)）で先に証明書を用意してから本番 nginx を有効化します。

証明書パス（スタンドアロン nginx 設定 `nginx/nginx.conf`）:

- `/etc/letsencrypt/live/seventeenwalk.taimanpoker.com/fullchain.pem`
- `/etc/letsencrypt/live/seventeenwalk.taimanpoker.com/privkey.pem`

### 3.2. 自動更新

Certbot は webroot 方式で更新し、証明書ボリュームを nginx と共有します。更新後は必要に応じて nginx を reload してください。

## 4. このプロジェクトに無いもの（ringgame との差分メモ）

SeventeenWalk には次はありません（手順書や compose に登場させないこと）:

- PostgreSQL / 永続 DB
- JWT・ログイン・招待コード
- `/api` プレフィックス付き REST
- ウォレット・cash_out・テーブル進行のスナップショット永続化
